### `api/releases.php` (called only by the release workflow)

- POST only; anything else answers 404 `{"error":"Not found."}`. Every request carries the header **`X-Release-Secret`**. The server's copy is `private/release-upload-secret.txt`: one line, at least 32 characters. Missing or shorter: 503 `{"error":"Release uploads are not set up on this server."}`. Different: wait 0.5 s (`usleep(500000)`), then 403 `{"error":"Not allowed."}`. Compare with `hash_equals`.
- **Chunk:** `POST ?action=chunk&name=<file>&offset=<bytes already sent>&total=<file size>`, body = the next piece of the file, `Content-Type: application/octet-stream`. Each piece is 1 byte to **8 MB (8 x 1024 x 1024)**; a file is at most 400 MB. The server appends to `download/files/<name>.part` and renames it to `<name>` when `received == total`. Answer 200 `{"received": <bytes on the server>, "complete": true|false}`. Offset 0 starts over (replaces any unfinished try). An offset different from what the server has: 409 `{"error":"Out of order.","received": <bytes the server has>}` (the client resumes from `received`). More data than `total`: 400 and the `.part` is deleted. Missing/invalid offset or total: 400 "Missing or invalid offset/total.". A piece of 0 bytes or over 8 MB: 400 "Each piece must be between 1 byte and 8 MB.". File names must match `^e-layout-(\d{1,3}\.\d{1,3}\.\d{1,4})(\.apk|-setup\.exe)$`, otherwise 400 "Not a release file name.". Platforms: `['android' => '.apk', 'windows' => '-setup.exe']`.
- **Publish:** `POST ?action=publish`, `Content-Type: application/json`, body:
  `{"version":"1.0.0","build":1,"date":"2026-11-15","platform":"android","file":"e-layout-1.0.0.apk","size":56941479,"sha256":"<hex>","changelog":{"1.0.0":["..."],"0.9.0":["..."]}}`.
  Checks: version `^\d{1,3}\.\d{1,3}\.\d{1,4}$`, build an integer of 0 or more, date `YYYY-MM-DD`, a known platform, sha256 64 hex, size 1 or more (400 "Missing or invalid release details." otherwise); the file name matches the version and platform (400 "The file name does not match the version and platform."); the file exists with that size and SHA-256 (409 "The uploaded file is missing or does not match its size and checksum."). Notes: at most 200 versions, 30 notes per version, 500 characters per note, control characters replaced by a space, empty notes dropped. Under an exclusive `flock` on `download/.publish.lock` (503 "The server is busy. Try again." if it can't lock): merge into `releases.json`, set this version's `build`, `date` and `files[platform]`, sort, delete files beyond the newest 3 per platform, write `releases.json` and `latest.json` atomically (write `.tmp`, then `rename`; 500 "The server could not save the release list." on failure). Answer 200 `{"ok":true,"version":"1.0.0","platform":"android","latest":{<that platform's latest.json entry>}}`.
- **Client** (`scripts/publish_release.py`): `User-Agent: elayout-release/1`; 8 MB pieces; up to 5 attempts per request on network errors and on 5xx, waiting 3 s x attempt; follows a 409's `received` up to 10 times; 120 s timeout per request; prints `<name>: NN%`; then publishes with the date in Manila time (UTC+8) and every version's notes from `assets/whats_new.md`. Any failure exits non-zero.

### `api/download.php` (counter)

`GET ?file=e-layout-1.0.0.apk`: when the name matches and the file exists, adds one to `private/download-counts.json` (`{"android":n,"windows":n}`, read and written under a file lock) and redirects 302 to `/download/files/<name>` with `Cache-Control: no-store`; otherwise redirects 302 to `/download/`. `GET ?action=stats`: `{"android":n,"windows":n,"total":n}` with `Access-Control-Allow-Origin: *` and `Cache-Control: no-cache`.

### The apps' update check (calendar `lib/app_update_service_io.dart`)

- GET latest.json with headers `Accept: application/json`, `Cache-Control: no-cache`, `User-Agent: elayout-app`; connection timeout 10 s; anything but 200 is an error.
- The entry is `windows` on Windows and `android` otherwise; a missing or null entry means "no download for this platform yet". Version string `"<version>+<build>"`. Newer when (major, minor, patch, build) compares greater; a leading `v` is ignored and each part keeps only its leading digits (`1.0.0-beta` → 1.0.0). Download address: `download`, else `url`, else `page`.
- Download into `<temporary folder>/updates/` as `e-layout-<version>-<build>.apk` or `e-layout-<version>-<build>-setup.exe`. Reuse an earlier download when its SHA-256 matches; otherwise delete everything else in that folder, download into `<file>.part` (connection timeout 15 s; the stream fails when no data arrives for 30 s), rename when complete, check the SHA-256 (on a mismatch delete the file and fail with "The downloaded update is damaged"). Progress is reported from 0 to 1 only when the whole percent changes, and is null while the size is unknown (`Content-Length`, else latest.json's `size`). Cancelling (cancelling the stream subscription) closes the file first (Windows can't delete an open file) and deletes the `.part`. Yields 1, then installs.
- **Android:** a `MethodChannel` call `installApk` with `{"path": <file>}`. `MainActivity` turns the path into a `content://` address with `FileProvider.getUriForFile(this, "$packageName.updates", File(path))` and starts `Intent(Intent.ACTION_VIEW).setDataAndType(uri, "application/vnd.android.package-archive").addFlags(Intent.FLAG_GRANT_READ_URI_PERMISSION or Intent.FLAG_ACTIVITY_NEW_TASK)`; errors come back as `result.error("install_failed", ...)`. Manifest: `<uses-permission android:name="android.permission.REQUEST_INSTALL_PACKAGES"/>` and a provider `android:name=".UpdateFileProvider"` (an empty `class UpdateFileProvider : FileProvider()` in `MainActivity.kt`, so it can't clash with a plugin's provider), `android:authorities="${applicationId}.updates"`, `android:exported="false"`, `android:grantUriPermissions="true"`, with `<meta-data android:name="android.support.FILE_PROVIDER_PATHS" android:resource="@xml/update_file_paths"/>`; `res/xml/update_file_paths.xml` is `<paths><cache-path name="updates" path="updates/" /></paths>` (`getTemporaryDirectory()` is the cache folder on Android). Android asks once to allow installs from the app.
- **Windows:** `Process.start(file, ['/SILENT', '/SUPPRESSMSGBOXES', '/NORESTART'], mode: ProcessStartMode.detached)`, then `exit(0)` so the installer can replace the files; the installer's last `[Run]` line reopens the app.
- **Wording** (calendar, to adapt): download dialog title "Updating to version {v}"; status "Downloading… {received} of {total} MB" (megabytes with one decimal), "Downloading…" while the size is unknown, "Opening the installer…" at 100%; hints for Android ("If your phone asks, allow installs from {app}, then tap Update. Your ... stay.") and Windows ("The app will close, update itself, and open again. Your ... stay."); failure "The update could not be downloaded. Check your internet connection and try again." with "Download in browser", "Cancel" and "Try again". Start-up dialog "Update available", "Version {v} is ready. Install it over this app to keep your data and settings.", that version's What's new list, buttons "Later" and "Update". About: "Version {v} is available." with "Update now", "You're up to date.", "Check for updates", "Could not check for updates right now.".

**Security rules (all are tested in `run_tests.py`):**
1. **Strict validation with readLayout's limits** (`lib/core/model/layout_codec.dart`): the body must decode (`json_decode`, depth 64) to an envelope `{"format":"pio-photo-layout","version":2,"layout":{...}}` whose layout has `"version":2` and an `elements` list (`array_is_list`) of 1 to 500 objects, each with `type` one of `text`, `shape`, `image`, `icon`; names at most 80 characters, `text` at most 4000, every other string at most 200; `assets` keys match `^[\w-]{1,64}$`, each `data` string is at most 40,000,000 characters and matches `^data:image/(png|jpeg|webp|gif|avif);base64,[A-Za-z0-9+/=]+$`, and its decoded bytes are confirmed by `getimagesizefromstring` to be that same type, at most 8000 x 8000; `fonts`: family names at most 80 characters, at most 18 faces each, `data` base64 shorter than 15,000,000 characters, `mime` matching readLayout's font pattern (`font/(ttf|otf|woff|woff2)`, `application/(x-font-ttf|x-font-otf|font-woff|font-sfnt|octet-stream)` or empty), and decoded bytes starting with `00 01 00 00`, `OTTO`, `true`, `wOFF` or `wOF2`. The stored file is re-encoded from the decoded data (`json_encode` with the `JSON_HEX_*` flags), with only `format`, `version` and `layout` at the top.
2. **Size limits:** the layout file at most 8 MB, the preview PNG at most 1 MB and at most 1200 x 1200; the request is refused before reading when `CONTENT_LENGTH` is over 10 MB. `api/.htaccess` already allows 13M posts.
3. **Rate limits:** at most 5 submissions per client per 24 hours, and at most 50 layouts waiting for review in total. The client is `REMOTE_ADDR`, or the server variable named by `CLIENT_IP_HEADER` only when the owner sets it (behind a proxy he trusts). Only an HMAC-SHA256 of the address is stored (key: `private/rate-key.txt`, 32 random bytes made on first use), in `DATA_DIR/ratelimit.json` under a file lock, pruned to 24 hours; raw addresses are never stored or logged.
4. **Storage outside the served folders:** `DATA_DIR/templates/{pending,approved}/<id>.json` and `<id>.png`, `DATA_DIR/templates/index.json` (metadata), `DATA_DIR/templates/rejected.log` (date, id, office; nothing else). Ids are `bin2hex(random_bytes(8))`; file names never come from the request. The health check reports `data_writable` and `data_outside_web_root` (true when `realpath(DATA_DIR)` is not inside `realpath($_SERVER['DOCUMENT_ROOT'])`), and the README tells the owner that on the live site the folder is `private/data/` behind `private/.htaccess` (Decision 11) and how to move it.
5. **Only JSON or PNG is ever served**, through `templates.php` with the headers above; nothing in `DATA_DIR` is reachable directly. The preview is decoded with GD (`imagecreatefromstring`) and written again with `imagepng`, so no other bytes survive. No executable or HTML upload is possible: the client's file name and MIME type are ignored, uploads are checked with `is_uploaded_file`, and anything that isn't a valid layout or PNG is refused.
6. **Admin password stored only as a hash** in the private config: `const ADMIN_PASSWORD_HASH = '<password_hash() output>';` (made with `php -r "echo password_hash(trim(fgets(STDIN)), PASSWORD_DEFAULT), PHP_EOL;"` so the password never appears in a command line). Empty: `/admin/` answers 503 "The review page isn't set up yet." Checked with `password_verify`. At most 5 failed sign-ins per client per 15 minutes (then 429 "Too many tries. Wait 15 minutes and try again."), each failure waits 0.5 s.
7. **Sessions and CSRF:** `session_name('elayout_admin')`, cookie `Secure` (when HTTPS), `HttpOnly`, `SameSite=Strict`, path `/admin/`; `session_regenerate_id(true)` after sign-in; signed out after 30 minutes idle. Every POST form carries a per-session token (`bin2hex(random_bytes(32))`) checked with `hash_equals`, and POSTs whose `Origin` (or `Referer`) host isn't the site's own are refused with 403. The page has no JavaScript.
8. **Output escaping:** every value printed in the admin HTML goes through `h()` = `htmlspecialchars($v, ENT_QUOTES | ENT_SUBSTITUTE, 'UTF-8')`; JSON output uses the `JSON_HEX_*` flags. Admin pages send `Content-Security-Policy: default-src 'none'; img-src 'self'; style-src 'self'; form-action 'self'; frame-ancestors 'none'; base-uri 'none'`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`; pending previews are shown only to a signed-in session (`/admin/?action=thumb&id=`).
